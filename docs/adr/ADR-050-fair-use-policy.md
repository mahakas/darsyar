# ADR-050: سیاست Fair-Use و abuse flag — تأییدشده

- **وضعیت:** accepted (تصمیم مالک — 2026-10-30)
- **هم‌راستا با:** R-137، R-138 (ADR-040)، R-139؛ ADR-039 (برای آستانهٔ billable)

## تصمیم تأییدشده

### شمارش
- سقف نرم ماهانه: **10,000 پیام قابل‌شمارش** به ازای کاربر/دوره.
- یک پاسخ دستیار = یک پیام (تعداد توکن ضرب نمی‌شود).
- پاسخی که به آستانهٔ billable (ADR-039) نرسد **شمارش نمی‌شود**.
- پاسخی که به آستانه برسد **شمارش می‌شود** (شامل پاسخ جزئی واجد شرایط).
- refund جبران داخلی واقعیت «مصرف برای سنجش Fair-Use» را پاک نمی‌کند.
- شمارش باید از `usage_events` قابل بازسازی باشد (R-139)؛ idempotency رویداد از شمارش تکراری جلوگیری می‌کند.
- ADR-039 بازتعریف نمی‌شود.

### Abuse flag
- پرچم بلافاصله وقتی **تعداد > 10,000** می‌شود ایجاد می‌شود (دقیقاً 10,000 → بدون پرچم).
- عبور از سقف **کاربر را مسدود نمی‌کند**؛ بدون تعلیق خودکار/بدون کسر خودکار.
- **حداکثر یک پرچم به ازای هر کاربر/دوره**؛ تاریخچه حفظ می‌شود.
- رسیدگی ادمین: ثبت actor، timestamp و دلیل؛ **حل‌کردن تاریخچه را حذف نمی‌کند**.
- Period بعدی می‌تواند پرچم مستقل جدیدی ایجاد کند.

### معماری داده (مستند، بدون کد)
- هویت دورهٔ Fair-Use: `YYYYY-MM` (ADR-040)؛ بازسازی از `usage_events` بر پایهٔ `created_at` UTC.
- **جدول جداگانهٔ fair-use flags** (نه `reconciliation_alerts` — آن جدول مسئولیت مالی/تطبیق جدا دارد).
- قید یکتایی `(user_id, period_key)` برای پرچم فعال/هر پرچم.
- رسیدگی auditable ادمین.
- ایجاد پرچم idempotent و امن در برابر هم‌زمانی (قید DB مرجع نهایی).
- بدون بلاک خودکار کاربر.

## پیامدها
- مهاجرت آینده: جدول `fair_use_flags` (+ ایندکس یکتای کاربر/دوره).
- تست‌ها: مرز 10,000 (درست/بیشتر)، یک‌بار بودن، هم‌زمانی، تاریخچه، resolution، دورهٔ جدید.
- فایل‌های متأثر: سرویس fair-use/abuse، مدل، مهاجرت، تست‌ها.
